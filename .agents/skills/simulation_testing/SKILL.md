# مهارة: محاكاة اختبار منصة سكن

## الهدف

محاكاة استخدام حقيقي للموقع بكثافة عالية، كأن عشرات الموظفين يعملون في نفس الوقت، ثم تقديم تقرير شامل ومنظم.

## الفريق (الشخصيات)

قم بإنشاء هؤلاء العوامل وتشغيلهم باستقلالية:

| الشخصية | الدور | الأولويات |
|---|---|---|
| المدير التنفيذي CEO | يراجع لوحة الإدارة والتقارير العليا | الأداء، الاستقرار، اتخاذ القرار |
| مدير المنتج | يقيّم سير العمل ومنطق العمليات | التدفق المنطقي، القيمة للمستخدم |
| مدير المشروع | يتعامل مع صفحات المشاريع والمشاركين | إدارة المشروع، ضبط الفريق |
| محلل الأعمال | يفحص البيانات والتقارير والفلاتر | دقة البيانات، اكتمالها |
| مسؤول الجودة QA | يبحث عن أخطاء برمجية وحالات حافة | الأخطاء، edge cases |
| مختبر اختراق Security | يحاول تجاوز الصلاحيات وسرقة الوصول | ثغرات الأمان |
| مهندس UX | يقيّم تجربة المستخدم والتصميم | قابلية الاستخدام، RTL، التناسق |
| مستخدم جديد | شخص يستخدم المنصة لأول مرة | الوضوح، سهولة الاستخدام |
| مستخدم محترف | شخص خبير يريد سرعة وكفاءة | الأداء، الاختصارات |
| معلم | يتعامل مع الحضور وبطاقات المشاركين | التحضير، المشاركون |
| مشرف | يراقب المشاريع ويرفع التقارير | التقارير، الإشراف |
| مدير النظام | صلاحيات كاملة، يختبر كل شيء | الإدارة، الضبط |
| موظف دعم فني | يحاول استيعاب المنصة لمساعدة الغير | التوثيق، الوضوح |

يجب أن **يختلف** تفكير كل شخصية عن الأخرى. لا تجعلها متفقة دائماً.

## أسلوب التنفيذ

### 1. البناء الداخلي للمحاكاة
قبل تنفيذ أي خطوة:
- **ناقش داخلياً** بين الشخصيات: من يبدأ؟ ما الاتفاقيات؟ ما الخلافات؟
- اختر أفضل قرار.
- ثم نفذ.

### 2. العمليات المطلوبة
نفذ كمية كبيرة من العمليات التالية:

**عمليات حساب:**
- تسجيل دخول / خروج / إعادة دخول
- نسيان كلمة مرور
- تعديل الملف الشخصي
- تغيير البريد الإلكتروني

**عمليات بيانات:**
- إنشاء / تعديل / حذف سجلات
- رفع وحذف ملفات
- بحث / فلترة / فرز
- نماذج ناقصة وبيانات خاطئة

**عمليات ضغط:**
- الضغط السريع على أزرار
- تحديث الصفحة أثناء عمليات
- فتح عدة تبويبات
- عمليات متزامنة

**عمليات حافة (Edge Cases):**
- نصوص عربية / إنجليزية / رموز خاصة
- أرقام طويلة جداً
- نصوص طويلة جداً
- ملفات كبيرة أو غير مدعومة

**اختبار الصلاحيات:**
- محاولة مستخدم عادي دخول لوحة الإدارة
- معلم يحذف بيانات لا تخصه
- تغيير معرفات في URL
- الوصول المباشر لصفحات محمية
- محاولة استغلال APIs

### 3. اكتشاف المشاكل المستهدفة

ركز على:
- مشاكل UX (تدفق، وضوح، إرشادات)
- مشاكل UI (تصميم، اتساق، RTL، Typography)
- بطء الأداء
- عمليات غير منطقية
- أزرار غير مفيدة أو صفحات مفقودة
- رسائل غير واضحة أو مربكة
- مشاكل أمنية وصلاحيات
- أخطاء برمجية وأخطاء إملائية

## التقرير النهائي المطلوب

بعد اكتمال المحاكاة، قدم تقريراً شاملاً يتضمن الأقسام التالية:

### 1. ملخص تنفيذي
- عدد العمليات المنفذة
- نسبة النجاح / الفشل
- أبرز الاكتشافات

### 2. الأخطاء المكتشفة
لكل خطأ:
- **الوصف:** ما هو الخطأ؟
- **درجة الخطورة:** (حرجة / عالية / متوسطة / منخفضة)
- **كيفية إعادة الإنتاج:** خطوات محددة
- **الحل المقترح**
- **الأولوية:** (فوري / هذا الإصدار / الإصدار التالي)
- **تأثيره على المستخدم**
- **تأثيره على العمل**

### 3. مشاكل الأمان والصلاحيات
- الثغرات المكتشفة
- محاولات التجاوز وما نتج عنها
- التوصيات الأمنية

### 4. مشاكل تجربة المستخدم
- نقاط الاحتكاك
- الخطوات غير الضرورية
- الارتباك في التنقل
- مشاكل RTL

### 5. اقتراحات التطوير
- ميزات جديدة لم يفكر بها المستخدم
- ميزات يجب إضافتها
- ميزات يجب حذفها أو تبسيطها

### 6. تقييم تجربة كل شخصية (1-10)
| الشخصية | التقييم | التعليق |
|---|---|---|
| ... | ... | ... |

### 7. خطة التطوير للدورة التالية
- قائمة بالأولويات مرتبة
- تقدير الجهد لكل بند

## قواعد حرجة

- **لا تختصر.** إذا وجدت خطأ، وثقه بالكامل.
- **لا تكتفِ بالتقرير.** نفذ المحاكاة فعلياً أولاً، ثم اكتب التقرير.
- **إذا لم تجد أخطاء واضحة،** افترض وجود نقاط ضعف محتملة وابحث بعمق أكبر.
- **لا تنهِ المهمة** حتى تنفذ المحاكاة كاملة وتكتب التقرير.
- استخدم بنية ملف `implementation_plan.md` أو `walkthrough.md` لتوثيق التقرير النهائي كـ artifact.

## ملاحظة للتنفيذ

قبل البدء:
1. اقرأ هيكل المشروع لفهم الصفحات الموجودة.
2. تحقق من نظام الصلاحيات والأدوار.
3. ادرس أهم المكونات (Projects, Participants, Attendance, Enjaz, Finance, etc).
4. ثم ابدأ المحاكاة.
